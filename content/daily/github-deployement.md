# Deploying a React + Vite Blog to GitHub Pages

After building my personal learning journal using React, Vite, TypeScript and Tailwind CSS, I wanted a simple way to publish it without managing servers or cloud infrastructure.

## Why GitHub Pages?

GitHub Pages is free, easy to set up, and works well for static websites generated by Vite.

It allows me to:

* Host a personal website for free
* Publish technical notes written in Markdown
* Keep content version-controlled in Git
* Share my learning publicly

## Project Structure

The blog is built around Markdown files stored in a content directory:

```text
content/
├── cloud/
├── algorithms/
└── system-design/
```

Each Markdown file contains frontmatter metadata and the article content.

The application discovers these files using Vite's `import.meta.glob()` and renders them dynamically using React.

## Deployment Steps

### 1. Configure the Vite base path

```ts
export default defineConfig({
  base: "/personal-learning/",
});
```

The base path must match the GitHub repository name.

### 2. Install gh-pages

```bash
npm install --save-dev gh-pages
```

### 3. Add deployment scripts

```json
{
  "scripts": {
    "predeploy": "npm run build",
    "deploy": "gh-pages -d dist"
  }
}
```

### 4. Build and deploy

```bash
npm run deploy
```

### 5. Enable GitHub Pages

Repository → Settings → Pages

Select:

* Source: Deploy from branch
* Branch: gh-pages
* Folder: / (root)

## Challenges Faced

### Frontmatter Parsing

Initially I wrote a custom parser for Markdown frontmatter.

It worked for simple fields but broke when handling arrays such as tags.

Switching to the `front-matter` package made the implementation more reliable and removed unnecessary complexity.

### GitHub Pages Routing

React Router's BrowserRouter does not work well with static hosting environments such as GitHub Pages.

Using HashRouter solved the issue without requiring server-side routing support.

## What I Learned

A key lesson from this project was that content systems should optimize for publishing speed.

My current workflow is:

1. Create a Markdown file
2. Commit the changes
3. Deploy the site

This allows me to focus on learning and writing rather than managing infrastructure.
